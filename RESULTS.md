# test_sber_credit_2026

## Подходы и слабые части

Для всех частей реализовал использование llm gemini от google и вариант без API, чтобы код запускался локально без ключей. 

### classify() и check_subject()

Без API был реализован поиск по ключевым словам/фразам и вычислена взвешенная уверенность в попадание по категориям

Ключевые слова строго заданы и не всеобъемлющи, что и является слабым местом такого подхода.

Перечень ключевых слов можно дополнить в config.

### extract()

Без API был реализован поиск полей по шаблону/регулярным выражениям. Были реализованы несколько шаблонов для каждого поля,
но существует вероятность, что они не покрыли все случаи. 

- для даты - 3 шаблона,

- для итоговой суммы - 3 формата числовой записи и 1 словесный,

- для ИНН - первое вхождение 10-12 цифровой записи после ИНН - слабое место: если первое вхождение не ИНН контрагента

- для контрагента - после ключевого слова, которое можно дополнить в config

- для предмета - 4 шаблона: путем поиска явного упоминания (Предмет договора: ), извлечения из скобок после глагола(поставить/выполнить ...),
извлечения из таблицы, извлечения из пронумерованного списка

### llm

Был сформулирован запрос и получен ответ в виде json нужной структуры

Ограничения: 

- количество запросов/токенов

- доступность в стране

- наличие доступа в сеть

- гарантии конфиденциальности документов, предоставляемых ИИ-агенту
